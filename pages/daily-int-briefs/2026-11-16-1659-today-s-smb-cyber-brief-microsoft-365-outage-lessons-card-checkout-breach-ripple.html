Today’s SMB Cyber Brief: Microsoft 365 outage lessons, card-checkout breach ripple effects, and AI app key theft

What small and medium-sized businesses should look out for today.

Moderate Monday 16 November 2026, 16:59 UK time
Today’s look-out: Cloud disruption + supplier breach follow-on scams + exposed SaaS/AI keys

What to look out for today

  • Microsoft 365 reliability and contingency planning: Microsoft says a months-old bug caused last week’s global Microsoft 365 outage via a cascading failure affecting networking gateway servers.
  • Payment card “checkout page” compromise: Ticket seller Fandango says hackers stole payment card details entered on its checkout pages. This type of incident often leads to follow-on fraud and convincing customer-support scams.
  • AI/SaaS key theft targeting: Amazon reports an “AI agent” campaign hunting weaknesses in internet-exposed AI apps (e.g. LiteLLM/One API/Dify) to steal API keys stored inside, then using stolen keys to power further searching.

Why this matters to smaller businesses

  • Business disruption: If you rely on Microsoft 365 for email, Teams, SharePoint/OneDrive, identity sign-in or line-of-business add-ins, an outage can halt work, invoicing, customer response and operations.
  • Financial impact: Card-theft incidents can trigger chargebacks, fraud queries, and reputational issues—plus increased scam calls/emails claiming to be “billing support”.
  • Unexpected cloud spend and data exposure: Stolen AI/provider API keys can lead to runaway costs, service suspension, and potential leakage of prompts/data if systems are misused.

Warning signs

  • Microsoft 365: staff reporting sign-in problems, Teams messages not sending, SharePoint/OneDrive files failing to open/sync, or repeated re-authentication prompts.
  • Payments: customers or staff seeing unexplained card transactions after a purchase; increased “did you make this payment?” calls; sudden spikes in refund requests.
  • API keys/AI apps: unusual usage spikes, unexpected bills, alerts about quota limits, new unknown integrations, or logs showing access from unfamiliar locations/services.

How attackers may exploit the situation

  • Outage-themed phishing: emails or calls claiming to be Microsoft/your IT provider asking users to “re-login”, “reconnect Teams”, or approve a new MFA prompt to fix access.
  • Refund/chargeback scams: criminals impersonating a merchant or payment support, offering a “refund”, and pushing victims to share card details, one-time codes, or install remote-support tools.
  • API key harvesting: attackers probing internet-exposed AI tooling and admin panels to extract stored provider keys, then using them for further automated scanning and expensive model usage.

What to do today

  • Agree your “M365 outage mode”: document how you’ll communicate (phone/SMS/WhatsApp), how to access critical contacts, and how to handle urgent customer requests if email/Teams is down.
  • Brief front-office/finance staff: treat outage/refund/billing calls and emails as high-risk today—verify via known numbers and avoid clicking “account fix” links.
  • Check key hygiene: inventory where AI/provider API keys are stored; rotate any keys that are shared widely or stored in web apps; enable alerts for unusual spend/usage where available.

Ask your IT provider

  • Resilience: “What is our agreed plan if Microsoft 365 is unavailable for a day—how do we access contacts, documents, and customer requests?”
  • Identity controls: “Do we have conditional access / sign-in alerts that would flag unusual logins during outage-themed phishing waves?”
  • Key management: “Do we have a register of API keys (AI, payment, comms) and a process to rotate and monitor them? Are any keys stored in internet-exposed tools?”
  • Web payment risk: “If we take card payments online, how are checkout pages monitored for tampering and how quickly would we detect a skimmer-type incident?”

Patch watch - only one short paragraph, and only if relevant

If you run any internet-facing Linux services (web/SSH), ask your IT provider to confirm they’re tracking the newly reported “NoisyTCP” issue that can crash some Linux servers under default configurations, and that protective mitigations/monitoring are in place while updates are assessed.

One action today

Send a short internal note today: treat any “Microsoft 365 fix”, “refund/chargeback”, or “urgent re-login” messages as suspicious and verify via a known phone number before taking action.
