Today’s SMB cyber lookout: MSP remote-tool compromises and “Google session” phishing

What small and medium-sized businesses should look out for today.

High Thursday 12 November 2026, 15:57 UK time
Today’s look-out: Supplier/MSP compromise risk + Google account session-hijack phishing

What to look out for today

1) MSP and remote support tool compromise risk: reports of active attacks abusing compromised ScreenConnect environments to push unauthorised remote-access tooling onto customer devices.

2) Google session hijacking phishing: a campaign using convincing links and calendar invites to trick staff into handing over access to live Google sessions (so passwords alone don’t save you).

3) Developer and supplier risk via GitHub account takeovers: hijacked GitHub accounts used to plant a “secret stealer” into repositories/CI workflows, potentially exposing credentials used by builds and deployments.

Why this matters to smaller businesses

  • MSP tooling is a force multiplier: if your IT provider’s remote management or support tool is misused, attackers can reach many customer machines quickly.
  • Session hijacking bypasses “we have MFA” assumptions: if an attacker steals a live session, they may access mail, files, or admin consoles without needing to re-enter credentials.
  • Supply chain ripple effects: even if you don’t use GitHub directly, your website/app vendor might. Stolen build secrets can lead to tampered updates, data access, or service disruption.

Warning signs

  • Unexpected pop-ups or installer prompts for remote access/support software, or a new “support” tool appearing on devices.
  • Emails/calendar invites urging you to “review a document”, “join a meeting”, “approve access”, or “restore your account”, especially with time pressure.
  • Unusual Google Workspace activity: sign-ins you don’t recognise, new browser sessions, new OAuth/third-party app access, or new forwarding/sharing rules.
  • IT supplier communications about “urgent re-install”, “new remote agent”, or “temporary access” that don’t follow your normal process.
  • For organisations with software/dev activity: unexpected CI failures, new workflow changes, or secrets/keys being rotated without explanation.

How attackers may exploit the situation

  • Compromised remote support tooling: attackers leverage trusted remote-control channels to deploy additional remote-access clients, move laterally, and steal data without triggering obvious alarms.
  • Calendar invite phishing + live proxying: staff click a link that looks safe; the attacker captures a live session and can act as the user (mail, files, approvals), sometimes in real time.
  • GitHub/CI secrets theft: attackers use stolen developer accounts to add code or workflow steps that exfiltrate credentials used for cloud hosting, deployments, or third-party services.

What to do today

  • Tell staff one simple rule: treat unexpected calendar invites and “document review” links as suspicious. Verify via a separate channel (Teams/phone) before clicking.
  • Lock down remote support: confirm who is allowed to initiate remote sessions, ensure sessions are logged, and require approval/notification for unattended access.
  • Review Google account security basics: check for unfamiliar sessions/devices, remove unknown third-party app access, and confirm MFA is enabled for all users.
  • If you use a web/app developer or agency: ask whether they’ve checked for unauthorised GitHub/CI changes and rotated exposed secrets.
  • Have a “supplier incident” script ready: if you receive an urgent message about remote tools or access changes, pause and verify authenticity before acting.

Ask your IT provider

  • Do we (or you) use ScreenConnect or similar remote support tooling, and have you checked for any suspicious changes or unauthorised remote agents on customer devices?
  • What alerts/logs do you have for: new remote access tools installed, new admin accounts, and remote sessions outside normal hours?
  • Can you show how you restrict remote access (least privilege, approval for unattended access, and audit logs we can review)?
  • What’s our process if a supplier tool is compromised—how quickly can you isolate endpoints and revoke remote access?
  • If we rely on a developer/agency: do they use GitHub and CI, and do they have a process to detect repo/workflow tampering and rotate secrets quickly?

Patch watch - only one short paragraph, and only if relevant

Microsoft has confirmed some recent Windows updates can cause SQL Server performance/stability issues. If you run line-of-business systems on SQL Server, ask your IT support to review whether you’re affected and to plan any remediation carefully to avoid unplanned downtime.

One action today

Send a same-day staff note: “Be wary of unexpected calendar invites and document links—verify via phone/Teams before clicking,” and remind everyone how to report suspicious invites/emails internally.
