Today’s SME cyber lookout: software supply‑chain risk (malicious npm packages) and safer use of AI coding tools

What small and medium-sized businesses should look out for today.

Moderate Sunday 20 September 2026, 19:46 UK time
Today’s look-out: Supplier & SaaS supply-chain risk (code dependencies) and developer tool safety

What to look out for today

Two practical risks for SMEs today:

  • Malicious code hidden in software dependencies (npm packages). A current campaign shows attackers can hide harmful behaviour in a library’s normal “runtime” activity, not just in install scripts.
  • Safety boundaries in AI coding tools. Researchers demonstrated a way to escape a locked-down coding sandbox and run commands on a developer’s machine (now patched), reinforcing the need for careful controls when staff use AI coding assistants.

Why this matters to smaller businesses

Many SMEs don’t write lots of software, but they often run websites, plugins, integrations, reporting scripts, automation, or small internal apps built by an in-house developer, an agency, or an outsourced IT partner. If a single dependency in that “chain” is compromised, it can lead to:

  • Website tampering or customer data exposure
  • Compromised cloud credentials or API keys used by apps and integrations
  • Business disruption (systems taken offline while code is audited and rebuilt)
  • Ripple effects to customers if you provide online services

Warning signs

  • Unexpected updates or new dependencies added to a web app, integration, or build pipeline
  • New outbound network connections from servers or apps that previously didn’t “phone home”
  • Unexplained spikes in CPU usage, background processes, or suspicious scheduled tasks on developer machines or build servers
  • Reports from your developer/agency that “a package was pulled/flagged” and needs urgent replacement
  • Staff using AI coding tools to run or test snippets directly on business machines without review

How attackers may exploit the situation

  • Dependency poisoning: attackers publish or compromise a software package so that malicious behaviour occurs during normal app use (runtime), making it harder for basic checks that only look at install scripts.
  • Credential harvesting: compromised code may try to access environment variables, API tokens, cloud keys, payment/CRM integration secrets, or browser-stored session data.
  • Developer machine pivoting: if a coding sandbox or tool is abused, the attacker’s aim is typically to reach the developer’s device, then access source code, tokens, customer data, or deployment systems.

What to do today

  • Confirm who maintains your code dependencies (internal dev, agency, MSP) and how they monitor for malicious packages or sudden package changes.
  • Reduce secret sprawl: ensure API keys and tokens are stored in a proper secrets manager (not in code, shared docs, or local .env files copied around).
  • Review admin access: limit who can deploy changes to websites/apps and who can modify build pipelines.
  • Set a “safe AI use” rule for developers: no running unreviewed AI-generated scripts on production systems; use a dedicated test environment; avoid pasting sensitive data into tools unless formally approved.
  • Be ready to roll back: confirm you can revert to a known-good release of any business-critical web app or integration quickly.

Ask your IT provider

  • Do we have an inventory of our business-critical apps/integrations and their key dependencies (including who built and who maintains them)?
  • How do you detect and respond to malicious or typosquatted packages in our software supply chain?
  • Where are our API keys/tokens stored, and can you show evidence they are rotated and access-controlled?
  • What controls are in place for developer laptops (EDR, least privilege, device encryption, rapid offboarding)?
  • Do you have guidance on approved AI coding tools and what data can/can’t be shared with them?

Patch watch - only one short paragraph, and only if relevant

OpenAI has patched the reported Codex sandbox escape; if your developers use AI coding assistants, ask your provider/team to confirm tools are up to date and that sensitive work is done in segregated development/test environments with strong access controls.

One action today

Ask whoever manages your website/apps (internal dev, agency or MSP) to confirm today that they monitor and control dependency changes (npm and similar) and can quickly roll back to a known-good build if a package is flagged.
