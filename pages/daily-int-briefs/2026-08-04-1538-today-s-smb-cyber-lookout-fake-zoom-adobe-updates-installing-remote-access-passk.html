Daily SMB Cyber Intelligence Brief

Today’s SMB cyber lookout: fake Zoom/Adobe updates installing remote access + passkey and software supply-chain risks

What small and medium-sized businesses should look out for today.

High Tuesday 04 August 2026, 15:38 UK time
Today’s look-out: Fake software update scams and remote access tool abuse (plus passkey & supplier/dev supply-chain risk)

What to look out for today

Be on alert for emails, chats, pop-ups and calls pushing urgent “Adobe” or “Zoom” updates, “document review” requests, or “system maintenance” fixes. Current campaigns are using these lures to install legitimate-looking remote access/remote management tools (notably ScreenConnect) to gain persistent control of business devices.

Also watch for increased noise around passkeys and software supply-chain issues: researchers describe ways that malware on an already-infected Windows PC could abuse Google-synced passkeys, and there are reports of malicious/poisoned npm packages spreading across many package names.

Why this matters to smaller businesses

  • “Real software” can be used for bad outcomes: remote support tools are common in SMEs, so an attacker installing one can blend in and bypass simple security checks.
  • Fast path to fraud and ransomware: persistent remote access often leads to mailbox access, finance system access, data theft and, in many cases, ransomware disruption.
  • Knock-on supplier risk: if you use an outsourced IT provider or support desk, staff may assume remote-access prompts are legitimate.
  • Passkeys aren’t magic if the device is already compromised: if a PC is infected, attackers may be able to piggyback on saved sign-in mechanisms.
  • Developer/website risk: even small orgs with a web agency or in-house developer could be impacted by poisoned dependencies, potentially affecting websites, portals, or internal tools.

Warning signs

  • Unexpected “update required” prompts for Zoom/Adobe appearing via email links, chat messages, or odd-looking web pages (especially outside normal update processes).
  • Requests to run a file, approve “remote support”, or allow a “technician” to connect when you didn’t raise a ticket.
  • New remote access software appearing on a device (or new desktop icons/services) that staff can’t explain.
  • Staff reporting the mouse moving on its own, new browser extensions, or frequent security prompts.
  • Unusual account activity: sign-in alerts, MFA/passkey prompts the user didn’t initiate, new forwarding rules, or new devices associated with accounts.
  • For teams that build software: sudden build failures, unexpected dependency changes, or new packages/versions appearing in lockfiles without clear reason.

How attackers may exploit the situation

  • Social engineering: convincing “update” or “maintenance” messages trick a user into installing remote access tooling that gives attackers persistent entry.
  • Living-off-the-land with admin tools: attackers prefer tools that look legitimate to reduce suspicion and make investigation harder.
  • Account takeover amplification: once on a machine, attackers may try to access email, cloud apps, and saved credentials; researchers also report methods that could abuse synced passkeys on already-compromised Windows devices.
  • Supply-chain poisoning: malicious packages (including npm ecosystem issues reported today) can introduce credential theft or remote control into developer workflows, then spread further.

What to do today

  • Staff message (10 minutes): “Don’t install Zoom/Adobe updates from links/messages. Updates only via approved method (Company Portal/IT tool/vendor app store). Report any ‘remote support’ prompt you didn’t request.”
  • Confirm your remote-support policy: who is allowed to remote in, what tool names are approved, and how staff verify a support request is real.
  • Review remote access inventory: ensure only approved remote tools are installed and monitored. Investigate any new or unexpected remote tool installs.
  • Harden sign-ins where you can: check for suspicious mailbox rules/forwarding, and review recent sign-ins for key accounts (finance, admin, payroll).
  • Developer/supplier check-in: if you (or your web agency) use npm, ask what monitoring is in place for dependency integrity and whether any emergency review is underway following today’s reports of poisoned packages.

Ask your IT provider

  • What remote access tools are approved in our environment, and how do you alert on new remote tool installs (e.g., ScreenConnect or similar)?
  • Do you have a process to verify support interactions (ticket-first, call-back number, shared phrases) so staff can spot fake “IT maintenance” requests?
  • What is your containment playbook if a device is suspected of having unauthorised remote access installed (isolation, credential reset, sign-in review)?
  • How do you monitor for mailbox rule abuse and suspicious sign-ins for Microsoft 365/Google Workspace?
  • If we rely on developers or an agency: what checks are in place for dependency/supply-chain issues (package vetting, lockfile review, anomaly detection) and what changed today in response to the reported npm poisoning?

Patch watch - only one short paragraph, and only if relevant

Today’s key issue is not a single patch but how updates are delivered: remind staff that software updates must only be installed via your approved update route (managed update tool, official app update mechanism, or IT-led process), not from links in emails, chats, or random pop-ups.

One action today

Send a same-day staff note: “No Zoom/Adobe updates from links or pop-ups; only via our approved update method—report any unexpected remote-support prompt immediately.”
