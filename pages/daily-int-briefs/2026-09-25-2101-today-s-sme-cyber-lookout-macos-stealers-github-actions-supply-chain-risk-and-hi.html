Daily SMB Cyber Intelligence Brief

Today’s SME cyber lookout: macOS stealers, GitHub Actions supply-chain risk, and high-noise website attacks

What small and medium-sized businesses should look out for today.

High Friday 25 September 2026, 21:01 UK time
Today’s look-out: Software supply-chain and endpoint credential-stealing risks (plus noisy website compromise attempts)

What to look out for today

  • macOS credential/data-stealing malware is evolving (PamStealer; MacSync). Expect more convincing lures and quieter persistence on Macs, including abuse of trusted Apple services and “phone-home” decryption that makes analysis harder.
  • Software supply-chain risk via GitHub Actions: previously-compromised “actions-cool” GitHub Actions reportedly reappeared and resumed executing malicious behaviour. This is a reminder that third-party CI/CD components can be a hidden route into builds and deployments.
  • Website/admin takeover attempts remain a common disruption path: WordPress and popular components are still a frequent target, and CISA also flagged active exploitation for issues including SharePoint and RouterOS. Even if you’re not “federal”, the attacker interest is a useful warning signal.

Why this matters to smaller businesses

SMEs often rely on a mix of Macs, cloud apps, and outsourced web/IT support. Infostealers on a single device can lead to mailbox compromise, invoice fraud, payroll diversion, and customer data exposure. Supply-chain issues (like compromised CI/CD actions) can affect you indirectly if your developer, web agency, MSP, or SaaS vendor uses impacted tooling. Finally, website compromise attempts can quickly become a trading disruption (defacement, SEO spam, redirects, or stolen admin access).

Warning signs

  • Mac users reporting unexpected prompts, security pop-ups, or requests to “allow” automation/accessibility permissions they don’t recognise.
  • Unexplained login alerts or new devices/sessions in Microsoft 365/Google/admin portals shortly after a Mac user installs/opens something.
  • Sudden changes in website admin users (new admin accounts), unexpected plugin/theme changes, or content/redirect changes.
  • Build/deploy pipelines behaving oddly: new workflow changes you didn’t author, unusual outbound connections during builds, or deployments happening outside normal release windows.
  • Router/internet issues that coincide with suspicious admin logins or configuration changes (especially if you use MikroTik).

How attackers may exploit the situation

  • Mac infostealers aim to capture saved passwords, browser sessions, cookies/tokens, and sometimes crypto-wallet or keychain-related data—then reuse access to email, accounting, and cloud apps to pivot into fraud.
  • Calendar/“trusted service” abuse can help malware blend in with normal traffic and update itself without obvious downloads.
  • CI/CD supply-chain compromise can inject unwanted code or leak secrets (API keys, deployment credentials) from build environments—impacting websites and apps you run or host for customers.
  • Website/admin takeover commonly leads to SEO spam, malicious redirects, or new admin accounts that persist even after a quick clean-up.

What to do today

  • Mac check-in: remind staff not to approve unusual system permission prompts. If a prompt looks odd, they should stop and report it.
  • Token hygiene: ensure MFA is enabled on email, accounting, and admin portals; review recent sign-in logs for unusual locations/devices.
  • Website basics: confirm you can identify all current WordPress/admin users; remove unknown accounts; ensure backups are working and restorable.
  • Supplier check: if you use a web agency/dev partner, ask what they use in their GitHub Actions/CI pipelines and whether they had any exposure to compromised third-party actions.
  • Prepare for invoice fraud: remind finance teams to verify any bank detail changes via a known-good channel (not email reply).

Ask your IT provider

  • Do we have visibility of Mac endpoints (managed AV/EDR, device management), and can we quickly isolate a suspected infected Mac?
  • Do we monitor for unusual cloud sign-ins (Microsoft 365/Google), impossible travel, and new OAuth app consents?
  • If we (or our suppliers) use GitHub Actions/CI: do we pin actions to known-good versions, review third-party actions, and rotate secrets when a supply-chain alert occurs?
  • For our website: who has admin access, how is it reviewed, and what’s the recovery plan if an admin account is silently added?
  • For routers/firewalls (especially MikroTik): who manages firmware/config changes and how do we detect suspicious logins/config edits?

Patch watch - only one short paragraph, and only if relevant

CISA added actively exploited issues to its KEV catalogue today, including items affecting WordPress core, Microsoft SharePoint and MikroTik RouterOS. For SMEs, treat KEV additions as a prompt to confirm your website platform, any on-prem SharePoint, and edge networking kit are under active maintenance by whoever supports you—and that internet-facing services aren’t being left to drift.

One action today

Run a 15-minute access check: review (1) Microsoft 365/Google recent sign-ins, (2) WordPress/admin users, and (3) any recent CI/CD workflow changes—escalate anything unfamiliar to your IT support immediately.
