SMB Cyber Daily: fake GitHub “authenticator” downloads, Gyazo breach fallout, and Teams file-type blocking

What small and medium-sized businesses should look out for today.

High Friday 18 September 2026, 17:25 UK time
Today’s look-out: Malware via trusted-looking developer sites + breach follow‑on phishing

What to look out for today

1) Fake GitHub repositories impersonating well-known software (including “LastPass Authenticator” lookalikes) to trick staff into downloading an information-stealing malware (“Rapuncel”).

2) Gyazo data breach impact: 23.6 million user records reportedly stolen. Expect follow-on phishing, password-spraying and “account verification” scams referencing Gyazo.

3) Microsoft Teams file risk controls: Teams will allow admins to block custom file extensions — useful for reducing risky attachments and file transfers through chat.

Why this matters to smaller businesses

  • SEO + “trusted” platforms works on busy teams: GitHub pages can look legitimate, rank well in Google, and bypass the instinct to be cautious.
  • Infostealers are a fast route to business compromise: once passwords/session tokens are stolen, attackers can jump into email, Microsoft 365/Google Workspace, finance tools, payroll, and customer systems.
  • Breach ripple effects are predictable: when a service has a large breach, scammers quickly use the brand name to make emails and calls feel credible.

Warning signs

  • Staff searching Google for an app and landing on a GitHub repo instead of the official vendor site/app store.
  • “Authenticator/2FA” tools offered as downloadable executables from repositories, file shares, or “releases” pages.
  • Emails or messages claiming “Gyazo security alert”, “your images will be deleted”, “verify your account” or asking to reset/confirm passwords.
  • Unexpected MFA prompts, unusual login alerts, or new mailbox rules/forwarding being created.
  • Teams chat used to share unusual file types or “quick tools” to install.

How attackers may exploit the situation

  • Malware distribution by impersonation: attackers publish polished GitHub repos branded as trusted products, then rely on search results and user urgency to get installs.
  • Credential and session theft: infostealers focus on browsers, saved passwords, and tokens — enabling account takeover even when passwords later change.
  • Breach-themed social engineering: if an employee ever used Gyazo (even personally), attackers can tailor messages to look like legitimate security notifications.
  • In-chat delivery: once one account is compromised, attackers may message colleagues/customers via Teams to spread links or files.

What to do today

  • Send a 2-minute staff warning: “Don’t install ‘authenticator’ or security tools from GitHub links found via Google. Use vendor websites/app stores only. If in doubt, ask IT.”
  • Check for Gyazo exposure: ask teams (marketing, design, training) whether Gyazo is used; if yes, ensure passwords are unique and MFA is enabled wherever possible.
  • Look for early takeover indicators: review recent sign-in alerts and any new email forwarding rules or suspicious inbox rules.
  • Reduce risky file delivery in Teams: plan to use Teams’ upcoming ability to block custom file extensions aligned to your organisation’s risk tolerance.

Ask your IT provider

  • Do we have controls to block or warn on new/untrusted software downloads, especially from file-sharing and code-hosting sites?
  • How quickly can we detect infostealer-style compromise (impossible travel, token theft symptoms, unusual mailbox rules)?
  • Are we monitoring for new email forwarding rules and suspicious OAuth/app consent events in our cloud accounts?
  • When Teams’ custom file extension blocking is available, what extensions will we block and how will exceptions be handled?

Patch watch - only one short paragraph, and only if relevant

No urgent patch-led SME action from today’s items. The practical focus is reducing risky downloads (fake GitHub repos) and tightening cloud identity monitoring; for organisations using AI coding agents, confirm your supplier has addressed plugin/repository supply-chain risks.

One action today

Message staff today: only download authenticator/security tools from the official vendor site or app store — never from GitHub links found via Google — and report any “Gyazo security alert” emails as suspicious.
