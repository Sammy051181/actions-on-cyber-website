Today’s SMB Cyber Brief: GitHub outage disruption + AI agent/MCP “secret leakage” risk

What small and medium-sized businesses should look out for today.

Moderate Monday 17 August 2026, 17:44 UK time
Today’s look-out: Cloud/SaaS disruption scams and secret exposure via AI tooling

What to look out for today

1) GitHub disruption: GitHub is reported as down for some users, affecting the website, API, Actions, pull requests and other features. This can break software builds, deployments and developer workflows.

2) AI agent / MCP server “quiet data exposure”: Reports highlight that MCP (Model Context Protocol) servers can accidentally expose sensitive business data through plaintext configuration, overly broad permissions and prompt-injection style tricks — sometimes before security teams even realise an MCP server exists.

Why this matters to smaller businesses

  • Business disruption: If you rely on GitHub Actions or repositories to build, deploy or host internal tools, an outage can delay releases, fixes, and customer work.
  • Scam risk rises during outages: Attackers commonly use high-profile downtime as cover for fake “support”, fake “status updates” and credential-harvesting messages aimed at staff.
  • Secret leakage is a fast route to account takeover: If AI tooling is connected to company systems, exposed tokens/keys/passwords can lead to email, cloud or finance system compromise even without malware.

Warning signs

  • Unexpected emails/DMs/calls claiming to be “GitHub Support” asking you to re-authenticate, share a one-time code, or “confirm your organisation admin”.
  • Messages urging urgent changes during downtime (e.g. “move your runners”, “install this hotfix tool”, “use this alternate login link”).
  • Developers or IT noticing new/unknown AI agent tooling, “MCP server” processes, or integrations appearing in environments without a clear owner.
  • Sudden authentication prompts for source control, CI/CD, or cloud providers that don’t match normal workflows.

How attackers may exploit the situation

  • Impersonation during SaaS incidents: Fake incident notifications and fake login pages to steal GitHub credentials, session tokens or MFA codes.
  • “Helpful” third-party tooling: Offering scripts/apps to “restore access” or “mirror repos” that really capture credentials or tokens.
  • AI agent / MCP secret harvesting: Poorly controlled MCP servers may expose API keys, access tokens or sensitive internal data if configuration is stored insecurely or permissions are too broad. Prompt-style manipulation may coax an agent into revealing secrets or performing unintended actions.

What to do today

  • Tell staff one simple rule for today: during outages, don’t trust inbound links or “support” messages. Use your normal bookmarks and official status pages you already know.
  • Confirm business continuity: if GitHub is part of your delivery process, agree what pauses (deployments/releases) are acceptable until service stabilises.
  • Lock down secrets: ensure no passwords/API keys are sitting in plaintext config files or shared docs. Rotate any keys/tokens if you suspect they may have been exposed.
  • Inventory AI integrations: if you use AI agents or developer assistants connected to company tools, identify who owns them and what data/tools they can access.

Ask your IT provider

  • Do we depend on GitHub (repos, Actions, runners) for any customer-facing or critical internal services, and what’s our fallback when it’s unavailable?
  • What monitoring/alerts do we have for unusual logins or permission changes in GitHub (especially org admin changes and new OAuth/app authorisations)?
  • Do we run or use any MCP servers or AI agents connected to business systems? Who owns them, and what permissions/secrets do they hold?
  • How are secrets stored and rotated (e.g. token vaulting), and do we regularly check repos and configs for accidental secret exposure?

Patch watch - only one short paragraph, and only if relevant

Microsoft is reportedly working on a patch for a Defender “ShieldBreak” zero-day, and there is separate reporting on a Windows Certificate Authority privilege issue (“Certighost”). For SMEs, the practical takeaway is to confirm your IT provider has a process to rapidly apply security updates for identity and endpoint security tooling, and to prioritise anything affecting core identity infrastructure.

One action today

Send a same-day internal note: “GitHub disruption = expect scams. Do not follow login links from emails/DMs; only use our saved bookmarks and report any ‘support’ requests asking for codes or passwords.”
