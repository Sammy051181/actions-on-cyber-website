Daily SMB Cyber Intelligence Brief

Malicious VS Code extensions: check what’s installed and lock down extension installs

What small and medium-sized businesses should look out for today.

Moderate Monday 10 August 2026, 09:50 UK time
Today’s look-out: Supplier/app store risk (developer tools) leading to credential theft

What to look out for today

Reports are highlighting malicious Microsoft Visual Studio Code (VS Code) extensions using the name “Solidity Pro” that were designed to steal browser wallet data and credentials (including API keys). Even if the specific extensions have now been removed from a marketplace, the bigger issue remains: trusted developer tools and add-ons can be abused to get into business systems.

Why this matters to smaller businesses

Many SMEs rely on outsourced developers, internal IT, web agencies, or staff who use coding tools. A single compromised workstation can lead to:

  • Stolen passwords and API keys (cloud services, finance tooling, website hosting, marketing platforms).
  • Business email compromise if credentials are reused or stored in browsers.
  • Knock-on supplier risk: attackers can use stolen keys to access customer data or deploy changes to websites/apps.

Warning signs

  • Staff reporting unexpected logouts, MFA prompts they didn’t trigger, or new “authorised devices”.
  • Unfamiliar VS Code extensions appearing, or extensions requesting unusually broad permissions.
  • Sudden API key usage spikes, unknown integrations, or unusual activity in developer platforms.
  • Browser-stored passwords being accessed or changed unexpectedly on a developer/IT machine.

How attackers may exploit the situation

  • Credential and token theft from the developer’s machine (browser, local config files, environment variables).
  • API key reuse to access cloud services, source code repos, hosting, CRM, or analytics tools.
  • Follow-on phishing using stolen contacts and internal information to make emails look convincing.

What to do today

  • Inventory VS Code extensions on any machines used for development or admin work; remove anything unknown or unnecessary.
  • Lock down extension installs (where possible) so only approved extensions can be added.
  • Rotate exposed secrets: if a developer workstation may have been at risk, rotate API keys/tokens and review recent usage.
  • Move secrets out of browsers: use a password manager and avoid storing sensitive credentials in browsers on admin/dev machines.
  • Check sign-in logs for key services (Microsoft 365/Google, code repos, hosting, finance tools) for unusual locations/devices.

Ask your IT provider

  • Do we have controls to restrict or approve developer tool extensions on company-managed devices?
  • How quickly would we detect and respond to stolen credentials/API keys (monitoring, alerts, log review)?
  • Which systems rely on API keys or service accounts, and do we have a documented rotation process?
  • Are developer/admin machines treated as higher-risk endpoints (stronger monitoring, tighter privileges)?

Patch watch - only one short paragraph, and only if relevant

No specific patch action is the focus here. This is mainly a tooling and access-control issue: reduce unapproved add-ons, tighten permissions, and review logs so you can spot credential theft quickly.

One action today

Today, ask whoever manages IT/dev machines to export a list of installed VS Code extensions and remove/disable anything not explicitly approved for work.
