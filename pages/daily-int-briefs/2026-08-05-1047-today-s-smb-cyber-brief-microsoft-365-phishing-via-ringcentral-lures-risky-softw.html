Today’s SMB Cyber Brief: Microsoft 365 phishing via “RingCentral” lures + risky software supply chain

What small and medium-sized businesses should look out for today.

High Wednesday 05 August 2026, 10:47 UK time
Today’s look-out: Credential theft and trusted-supplier impersonation (voice/UC + Microsoft 365), plus trojanised downloads and developer add-ons

What to look out for today

1) Microsoft 365 login theft using “RingCentral” lookalike pages. A phishing-as-a-service operation is spoofing RingCentral branding to capture Microsoft 365 accounts, using more advanced techniques than basic fake login pages.

2) “Trusted download” and developer-tool supply chain risk. Reports highlight trojanised Windows installers (VPN/acceleration tooling), compromised Xcode projects/GitHub repos targeting macOS developers, and extensions impersonating legitimate developer tools while harvesting environment data.

3) AI-agent security incidents (testing boundary issues). Several stories this week show how automation/agents can be prompted or mis-scoped to take unintended actions in real systems—relevant if you use AI agents/bots with access to tickets, code, admin tools, or comms.

Why this matters to smaller businesses

  • Microsoft 365 accounts are a common “master key”. If attackers get one mailbox, they often pivot to invoice fraud, payroll changes, supplier payment diversion, and data theft.
  • RingCentral/UC brands are familiar in offices. Familiar branding reduces suspicion, especially for remote/hybrid staff.
  • Supply-chain compromise bypasses “be careful what you click”. If staff or your IT supplier installs a trojanised tool/extension, it can look legitimate while enabling persistence or data access.
  • Outsourced IT and developers are high-leverage targets. One compromised admin/developer device can impact many systems and clients.

Warning signs

  • Emails or messages claiming you must re-authenticate or reconnect RingCentral/voice services to Microsoft 365.
  • Unexpected Microsoft sign-in prompts, especially requests to approve a sign-in when you weren’t logging in.
  • Staff reporting they were asked to log in after clicking a “voicemail”, “missed call”, “fax”, or “account warning” style message.
  • New software/extensions appearing on PCs/Macs without a clear business request, especially “productivity”, “VPN”, “network acceleration”, or “developer helper” tools.
  • Developers noticing unusual changes in shared code projects, new dependencies, or strange pull requests/issues that try to get automation to run.

How attackers may exploit the situation

  • Session/credential theft to access Microsoft 365 (mailbox, OneDrive/SharePoint, Teams) and then send convincing internal phishing from a real account.
  • Invoice and payment diversion by monitoring email threads and inserting “updated bank details” at the perfect moment.
  • Abuse of trusted platforms (GitHub repos, extension marketplaces, installers) so the victim “installs the malware themselves” thinking it’s legitimate.
  • Agent/bot misdirection where automated helpers (triage bots, code assistants, ticketing automations) are manipulated into taking privileged actions or spreading unsafe changes.

What to do today

  • Remind staff: treat “RingCentral/Microsoft 365 re-login” messages as suspicious; use bookmarks for logins; never approve unexpected sign-in prompts.
  • Harden Microsoft 365 access: ensure MFA is enabled everywhere and review conditional access and sign-in alerts (at least for admin and finance accounts).
  • Finance control check: require a call-back (using a known number, not the email signature) for any bank detail changes or urgent payment requests.
  • Software hygiene: restrict who can install new software/extensions; review recently installed browser/editor extensions and remove anything unapproved.
  • If you use AI agents/bots: confirm what data/actions they can access; disable auto-actions that can change code/config without human approval.

Ask your IT provider

  • Are we seeing new Microsoft 365 sign-in risks (impossible travel, unfamiliar device logins, repeated MFA prompts) in the last 7 days?
  • Do we have phishing-resistant controls for key users (admins, finance, payroll), and are mailbox forwarding rules monitored?
  • What’s our policy for software and extension installation (Windows, macOS, browsers, VS Code / forks), and can you provide an “approved list”?
  • If we use automation/agents (helpdesk, code, security tools), what guardrails prevent them from taking privileged actions based on untrusted inputs?

Patch watch - only one short paragraph, and only if relevant

US authorities have flagged active exploitation of issues in commonly used server/admin software (including Tomcat and an RMM tool used by IT providers). For SMEs, the key takeaway is to ask your IT/support partner to confirm their internet-facing systems and remote management tooling are being actively monitored and updated, because compromises there can affect many customers quickly.

One action today

Send a 2-minute internal alert: “Do not re-login to Microsoft 365 from RingCentral/voicemail links; use bookmarks; report any unexpected MFA prompts immediately.”
