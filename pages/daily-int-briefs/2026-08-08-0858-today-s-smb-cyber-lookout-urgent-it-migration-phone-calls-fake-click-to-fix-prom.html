Daily SMB Cyber Intelligence Brief

Today’s SMB cyber lookout: urgent ‘IT migration’ phone calls, fake ‘Click to fix’ prompts, and risky software dependencies

What small and medium-sized businesses should look out for today.

High Saturday 08 August 2026, 08:58 UK time
Today’s look-out: Account takeover scams via phone + fake-fix prompts + supplier/dependency risk

What to look out for today

Three themes that are likely to hit smaller organisations (and their staff personally) even if you’re not a “big target”:

  • Vishing (voice phishing) aimed at stealing SaaS data: attackers posing as an IT help desk and pushing an “urgent security migration”, often contacting staff via personal phones.
  • “ClickFix” style fake-fix messages on Macs: prompts that try to trick users into running “fixes” that actually steal passwords and other stored credentials.
  • Supplier/dependency risk from malicious npm packages: a large cluster of malicious packages has been found, increasing the chance of a developer or IT supplier accidentally pulling in a harmful dependency.

Why this matters to smaller businesses

SMEs rely heavily on SaaS (Microsoft 365/Google Workspace, accounting, CRM, payroll, e-signature). If an attacker convinces one staff member to approve access, reset MFA, or run a “fix”, they can quickly:

  • Take over email and use it to request payment changes or intercept invoices.
  • Access shared files, client data, and mailboxes for extortion.
  • Move laterally into other systems using saved passwords, browser sessions, or SSO.
  • Create real operational disruption (locked-out accounts, halted billing, missed payroll deadlines).

Warning signs

  • A call or voicemail claiming to be “IT support” insisting on a mandatory, urgent migration or “security upgrade”.
  • Pressure tactics: “You’ll lose access in 30 minutes”, “Your account is compromised”, “We need to do this now”.
  • Requests to read out MFA codes, approve a sign-in prompt, or install a “support tool”.
  • On macOS: a web page or pop-up that looks like guidance and asks you to run a “fix” to proceed.
  • Unusual developer activity: new/unknown packages appearing in builds, or sudden dependency changes from a supplier.

How attackers may exploit the situation

  • Phone-first attacks: using personal numbers to bypass corporate controls, then guiding the user to approve access, reset MFA, or hand over details that enable SaaS takeover.
  • Fake ‘fix’ instructions: convincing a Mac user to run steps that lead to credential theft (saved browser passwords, keychain-related data, cached credentials).
  • Supply chain/dependency insertion: malicious npm packages can land in internal tools, websites, or automation scripts via typosquatting/random package names, then steal credentials or provide remote access.

What to do today

  • Tell staff: no IT team will ever ask for MFA codes or demand immediate action over the phone. Hang up and call back using a known internal number.
  • Enable/confirm phishing-resistant MFA where possible (or at least enforce MFA and reduce “push approval” risk with number matching/approval safeguards where supported).
  • Review who can reset MFA, add new authentication methods, create inbox rules, or add OAuth/app access in your SaaS.
  • For Macs: remind staff not to run copy/paste “fix” steps from a web page or pop-up. If something looks broken, report it to IT.
  • If you use developers or a web agency: ask how they screen dependencies and control package additions (especially npm).

Ask your IT provider

  • What controls do we have to reduce MFA bypass and “push fatigue” approvals in our main SaaS?
  • Can we alert on and review: new MFA method added, new device enrolled, mass mailbox forwarding rules, and new OAuth/app consent?
  • Do we have a call-back verification process for any account or security change requests?
  • For any software/dev work: what is our process to detect and block malicious or unexpected npm dependencies before deployment?

Patch watch - only one short paragraph, and only if relevant

No general “patch now” item from today’s stories is aimed at typical office patching. The practical focus is identity and access controls (MFA, sign-in alerts, limiting who can reset authentication) and safe user behaviour against phone-led scams and fake-fix prompts.

One action today

Send a same-day staff note: “We will never ask for MFA codes or urgent ‘security migrations’ over the phone—hang up, report it, and only call IT back via the known number.”
